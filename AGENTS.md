# englishstudentgames

## What this is

Portal with HTML games for learning English. All UI in **Spanish**. Deployed via GitHub Pages at `englishstudentgames.com` (set in `CNAME`).

**No build step, no framework, no tests, no CI.** Every page is one self-contained HTML file with inline CSS and inline JS. Edit the file, reload the browser.

Line endings are normalized to LF by `.gitattributes`. Keep it that way: a CRLF checkout turns a one-line edit into a whole-file diff and buries the review.

### The portal (`index.html`)

- The grid is **static HTML**: one `<div class="game-card" data-category="...">` per game. Nothing is generated by JS.
- Filter buttons carry `data-filter="all|phrasal-verbs|gerund-infinitive"`; one small inline script toggles the `.hidden` class on cards by comparing `data-filter` with `data-category`.
- Card link targets live in each card's `<a href>`; the filter, the card and the game's `data-category` are three separate hand-written strings that must agree.

## Games

### Phrasal Verbs — Memorización (`games/phrasal-verbs/game1.html`)

- Data: `const PHRASAL_VERBS` — memory cards with the verb, its Spanish meaning and an example sentence.
- Modes: `const MODES = ['MEANING', 'BLANK', 'REVERSE']`, with labels in `MODE_LABELS` and prompt copy in `MODE_PROMPTS`. The mode is drawn at random per card.
- Four multiple-choice options; a wrong answer re-queues the card (`queue.push(current)` inside `answer()`), so the round ends only when every card was answered right.
- Elapsed timer, streak counter, learned set, progress bar, and an end screen that lists the mistakes sorted by error count.
- Uses the shared `site-header` (taskbar link back to the portal) and `site-footer`.

### Phrasal Verbs — Memory / classification (`games/phrasal-verbs/game2.html`)

- Data: `const DATA`; themes: `const CATS = PEOPLE, COMM, MONEY, MOVE, LIFE, BODY`.
- Mechanic: pick one of six theme buttons for each phrasal verb.
- HUD with progress, right, wrong, current streak and best streak; progress bar; **no timer**.
- Each item carries a `hint` (why it belongs to its theme) shown when the answer is wrong.
- Misses are **not** re-queued; they accumulate in `stats.missed` and are listed on the end screen ("Para repasar"), with grade bands computed from the percentage.

### Gerund & Infinitive Trainer (`games/gerund-infinitive/game3.html`)

- Data: `const ITEMS` — three lines per item: a rule/example pair plus a `c` flag (`'g'` gerund, `'i'` infinitive with *to*, `'b'` bare infinitive). Labels in `const CAT`.
- The three answer buttons (`answer('g'|'i'|'b')`) are the modes; the correct category is the item's `c`.
- Per-item hint, round counter, streak with escalating combo messages, per-category result breakdown, restart-confirm overlay, keyboard shortcuts `1`/`2`/`3` to answer and `Enter`/`Space` to continue (`Escape` closes the overlay); **no timer**.
- Retry reinforcement: items missed in the previous round are re-added ×3 by `buildDeck` via `prevMissedWords`.

### Phrasal Verbs — Significados (`games/phrasal-verbs/game4.html`)

- Data: `const PHRASAL_VERBS` — 150 entries with `pv`, `meaning` (contextualised Spanish gloss), `others` (secondary meanings, often empty), `group` on entries that need anti-ambiguity, `example` (the target form wrapped in `{{...}}`) and `translation` (Spanish rendering of the example).
- Start screen picks the round size: `startGame(10 | 15 | 20)`, dealt from a shuffled pool of all 150 entries.
- Mechanic: one prompt and four options built by `pickDistractors(item, amount)`, which skips meanings that are equivalent (`normalizeMeaning`) or that share the entry's `group`.
- Feedback (`feedbackDetails`) shows the English example with the target form highlighted, its Spanish translation and the `others` meanings.
- A wrong answer re-queues the card at the end of the queue (`answer()`), so the round ends only when every card of the round was answered right at least once.
- HUD: Aciertos (`learned`/`total`), En cola (`queue-count`), Errores (`wrong-count`), Racha (`streak`), Tiempo (`timer`) and a progress bar. The end screen reports percentage, time, attempts, errors, best streak and a review block; `showStart()` starts another round.
- Uses the shared `site-header` (linking back to the portal) and `site-footer`. Nothing is persisted between rounds or sessions.

## Editing rules

- Every user-facing string is **Spanish**. Code, comments, docs and commit messages stay English.
- Adding a game: write `games/<theme>/gameN.html` as a self-contained page, then in `index.html` add one `<div class="game-card" data-category="<theme>">` with its own `<a href>`, and add a `<button data-filter="<theme>">` if the theme is new. There is no JS registry to update.
- Counts and copy are **hand-maintained**, so they drift the moment a data array changes. Current truth:

  | Where | Hardcoded | Real count |
  | --- | --- | --- |
  | `index.html` card 1 (description + tag) | `90 phrasal verbs` | 90 |
  | `index.html` card 2 (description + tag) | `91 phrasal verbs` | 91 |
  | `index.html` card 3 (description + tag) | `84 ejercicios` | 84 |
  | `index.html` card 4 (description + tag) | `150 phrasal verbs` | 150 |
  | `index.html` header counter | `<span>4</span> juegos disponibles` | 4 |
  | `game1.html` subtitle and "los 90" copy | `90` | 90 |
  | `game2.html` header copy | `91` | 91 |
  | `game3.html` `<span id="tot">` | `84` | 84 (also set at runtime by `render()`) |
  | `game4.html` subtitle | `150` | 150 |

  All hardcoded counts now match the data arrays. When you touch a game, fix its own labels; updating the portal cards is a copy change, so ask before doing it as a side effect.

## PWA

The site is a PWA (Progressive Web App) — installable on Android (via the install button or "Add to home screen") and iOS (via Share → "Add to Home Screen").

- `manifest.webmanifest` — app name, icons, colors. `start_url` and `scope` are `/`.
- `sw.js` — service worker. HTML is **network-first with cache fallback** (updates arrive as soon as there's connectivity); everything else is **cache-first with background update**. Bump `CACHE_VERSION` at every deploy so the new cache replaces the old one.
- `pwa.js` — shared script loaded by every page. Registers the SW, shows the install UI, remembers "Ahora no" for 7 days, hides everything once installed.
- `icons/` — PNG icons in 192, 512, maskable-512, 180, and 32, plus an SVG.

When adding a new game, add its path to the `PRECACHE` array in `sw.js` and bump `CACHE_VERSION`.

## Preview

Serve the repo over HTTP and open the portal, then follow the cards:

```bash
python -m http.server 8000    # or: npx serve .
```

Do **not** judge layout from `file://`: the portal footer links `href="/"`, which points at the filesystem root instead of the site root. Relative links between pages work fine under a server.
